متطلبات التشغيل

  • Node.js الإصدار 20 أو أحدث
  • pnpm الإصدار 9 أو أحدث
  • Git (أحد الإصدارات المستقرة)
  • حساب Firebase مع مشروع مفعّل (المصادقة + Firestore)
  • حساب Google لمفتاح Gemini API (للذكاء الاصطناعي)

خطوات التثبيت

1

تثبيت أدوات التشغيل

تأكد من تثبيت Node.js و pnpm على جهازك:

node -v
npm install -g pnpm
pnpm -v
2

نسخ المشروع أو سحبه

انسخ مجلد المشروع إلى المسار المطلوب أو اسحبه من المستودع:

git clone https://github.com/weeshi/lyalina-ads-manager.git
cd lyalina-ads-manager

أو افتح مجلد المشروع مباشرةً في محرر الأكواد (VS Code).

3

تثبيت الاعتماديات

pnpm install

يتم تنزيل جميع المكتبات المطلوبة من ملف package.json.

4

إعداد متغيرات البيئة

انسخ ملف .env.example إلى .env وعبّئ قيم Firebase الخاصة بمشروعك:

copy .env.example .env
المتغيرالوصف
VITE_FIREBASE_API_KEYمفتاح Firebase
VITE_FIREBASE_AUTH_DOMAINنطاق المصادقة
VITE_FIREBASE_PROJECT_IDمعرف المشروع
VITE_FIREBASE_STORAGE_BUCKETحاوية التخزين
VITE_FIREBASE_MESSAGING_SENDER_IDمعرف المرسل
VITE_FIREBASE_APP_IDمعرف التطبيق
VITE_FIREBASE_MEASUREMENT_IDمعرف القياس
تنبيه: لا ترفع ملف .env إلى أي مستودع عام؛ فهو مستبعد من Git عبر .gitignore.
5

تشغيل خادم التطوير

pnpm dev

يفتح التطبيق في المتصفح على العنوان http://localhost:3000.

6

التحقق من البناء (اختياري)

pnpm build

يُنشئ مجلد dist الجاهز للنشر في الإنتاج.

تثبيت سريع بأمر واحد (bootstrap)

أسهل طريقة لتجهيز المنصة على أي جهاز جديد — أمر واحد يفحص المتطلبات، يجهّز ملف .env، يثبّت الاعتماديات، ويشغّل خادم التطوير:

pnpm bootstrap

يقوم المعالج تلقائياً بـ:

  1. فحص جاهزية المتطلبات (Node.js, pnpm, git, Firebase CLI) مع تنبيهات واضحة.
  2. إنشاء ملف .env من .env.example إن لم يكن موجوداً، وفتح معالج التثبيت لملء القيم.
  3. سؤالك تفاعلياً عن قيم Firebase (أو تخطٍّ في الوضع الآلي --ci).
  4. تثبيت الاعتماديات عبر pnpm install.
  5. عرض الخطوات التالية وتشغيل خادم التطوير عند الطلب.
الخيارالوصف
pnpm bootstrapوضع تفاعلي كامل
pnpm bootstrap --ciوضع آلي غير تفاعلي (للنصوص البرمجية/CI)
pnpm bootstrap --no-devعدم المطالبة بتشغيل خادم التطوير
نصيحة: يظهر معالج الإعداد الأولي (Setup Wizard) تلقائياً داخل التطبيق عند تشغيله إذا كانت إعدادات الاتصال بقاعدة البيانات غير مكتملة — يسهّل تعبئة .env وتوليد firebaseConfig.ts دون الحاجة لسطر أوامر.

ملف الإعدادات المركزي (config) - الزرع

جميع إعدادات الاتصال بقاعدة البيانات (Firebase) ومفتاح الذكاء الاصطناعي معزولة في ملف واحد قابل للزرع:

src/config/firebaseConfig.ts

عند نقل النظام إلى بيئة جديدة أو قاعدة بيانات أخرى، عدّل القيم المزروعة في أعلى هذا الملف فقط (لا حاجة لتعديل باقي الكود). النظام يطبّق القيم المزروعة مباشرة، ويُعطي الأولوية لمتغيرات .env إذا وُجدت (غير فارغة).

القيمة المزروعةالوصفتجاوزها من
apiKeyمفتاح FirebaseVITE_FIREBASE_API_KEY
authDomainنطاق المصادقةVITE_FIREBASE_AUTH_DOMAIN
projectIdمعرّف المشروعVITE_FIREBASE_PROJECT_ID
storageBucketحاوية التخزينVITE_FIREBASE_STORAGE_BUCKET
messagingSenderIdمعرّف الإرسالVITE_FIREBASE_MESSAGING_SENDER_ID
appIdمعرّف التطبيقVITE_FIREBASE_APP_ID
measurementIdمعرّف القياسVITE_FIREBASE_MEASUREMENT_ID
appId (المسار)مسار البيانات داخل Firestore (artifacts/{path}/...)VITE_FIREBASE_APP_PATH
geminiApiKeyمفتاح Gemini AIVITE_GEMINI_API_KEY
مستوى أمان: المفاتيح الحساسة (apiKey, appId, geminiApiKey) مفتوحة بفتحات PASTE_YOUR_... في الملف المزروع. الأفضل وضع هذه الثلاثة في ملف .env (المستبعد من Git) وترك قيم المشروع العامة (projectId, authDomain...) في config. يمكنك اختيار الأسلوب الذي يناسبك — الأولوية دائماً لمتغيرات .env.
نصيحة: لتجهيز ملفات config و.env تلقائياً، استخدم معالج التثبيت (Wizard).

الإعداد على Firebase

لاستخدام قاعدة البيانات والمصادقة يجب تجهيز مشروع Firebase:

  1. ادخل إلى Firebase Console وأنشئ مشروعاً جديداً.
  2. فعّل خدمة Authentication واختر مزوّد Email/Password.
  3. فعّل خدمة Firestore Database واختر موقعاً قريباً.
  4. انسخ بيانات الإعداد من (إعدادات المشروع ← عام ← تطبيقاتك) إلى ملف .env.
  5. أضِف أذونات الأمان لقراءة/كتابة المقصود للمصادقين.
نصيحة: استخدم بيانات مشروع lyalina-ads الحالي إذا كنت تعمل على البيانات الفعلية.

النشر على Firebase Hosting

# تسجيل الدخول (مرة واحدة)
npx firebase login

# بناء ونشر
pnpm deploy

أو يدوياً:

pnpm build
npx firebase deploy --only hosting

المشروع المربوط حالياً: lyalina-ads

النشر عبر Docker (حاوية)

لنشر المنصة بشكل متسق في أي بيئة (سيرفر، خادم سحابي، Docker Swarm/Kubernetes) بدون الحاجة لتثبيت Node محلياً.

البناء والتشغيل بـ docker compose

# قيّم المتغيرات في ملف .env (تُقرأ تلقائياً) ثم:
docker compose up -d --build

يُبنى التطبيق (Node 20) ويُقدَّم عبر Nginx مع دعم التوجيه (SPA) على المنفذ 8080: http://localhost:8080

البناء يدوياً (تمرير القيم عبر build-args)

docker build \
  --build-arg VITE_FIREBASE_API_KEY=AIza... \
  --build-arg VITE_FIREBASE_PROJECT_ID=my-project \
  -t lyalina-ads-manager .

docker run -p 8080:80 lyalina-ads-manager
الملفالوظيفة
Dockerfileبناء متعدد المراحل (Node → Nginx)
docker-compose.ymlتنسيق البناء والتشغيل بمتغيرات من .env
nginx.confإعداد Nginx مع دعم توجيه SPA والضغط
.dockerignoreاستبعاد ملفات غير ضرورية من الحاوية
ملاحظة: تمرر قيم Firebase كوسائط بناء (build-args) لأنها تُدمج في حزمة الجافاسكربت أثناء البناء. راجع أيضاً src/config/firebaseConfig.ts للزرع الدائم داخل الكود.

حل مشاكل شائعة أثناء التثبيت

الأمر pnpm غير معروف: ثبّت pnpm عالمياً: npm install -g pnpm.
خطأ في متغيرات البيئة: تأكد من إنشاء ملف .env وملئه بالقيم الصحيحة.
رفض الاتصال بـ Firebase: تحقق من أن ملف .env يحتوي قيم المشروع الصحيح، وأن المشروع مفعّل.
منفذ مشغول: التطبيق يستخدم المنفذ 3000؛ حرّره أو غيّره في إعدادات Vite.
يظهر معالج الإعداد الأولي باستمرار: هذا يعني أن إعدادات الاتصال بقاعدة البيانات غير مكتملة (لا يزال بعضها placeholder أو يفقد القيم). املأ VITE_FIREBASE_* في ملف .env، أو زرع القيم في src/config/firebaseConfig.ts، ثم أعد تحميل الصفحة.
